# 第13章实验报告

## 1. 实验名称

保护模式微型内核加载用户程序，并由用户程序读出磁盘上的文本。

## 2. 实验目的

- 由 MBR 动态构造 GDT，把内核读入内存并进入保护模式。
- 内核识别 CPU，加载用户程序，再把控制权交回内核。
- 用户程序通过内核例程读取逻辑扇区 100 的 `diskdata.txt` 并显示。

## 3. 实验环境

| 项目 | 值 |
| --- | --- |
| 系统 | Ubuntu，NASM 2.16.01，QEMU 8.2.2 |
| 源文件 | `c13_mbr.asm`、`c13_core.asm`、`c13.asm`、`diskdata.txt` |
| 磁盘布局 | 扇区 0：MBR；扇区 1：内核；扇区 50：用户程序；扇区 100：磁盘数据 |
| 实验时间 | 2026-10-24 |

## 4. 实验原理

MBR 仍然在实模式里准备 GDT、A20 和 `CR0.PE`，然后把内核从扇区 1 读到约定的物理地址。内核在保护模式下提供字符串显示和读硬盘例程。

用户程序带有长度、入口和符号表。内核按扇区 50 加载它，调用其入口；用户程序再请求内核读取扇区 100。`diskdata.txt` 以普通文本放在该扇区，内容是一段关于 Intel386 的说明，末尾有 `[END]`。

## 5. 实验步骤

```bash
cd c13
sh run.sh
```

实测产物大小：MBR 512 字节，内核 4475 字节，用户程序 1979 字节。镜像 200 扇区。

## 6. 关键代码说明

内核先打印保护模式已生效的句子，再用 `CPUID` 得到品牌字符串。QEMU 的品牌字符串是 `QEMU Virtual CPU version 2.5+`。

用户程序打印固定边框 `**********User program is runing**********`，其中 `runing` 是源字符串里的拼写。然后逐段显示扇区 100 的文本，最后调用返回例程。内核补上一句控制权已经回来。

## 7. 实验结果

```text
  If you seen this message,that means we are now in protect mode,and the system
core is loaded,and the video display routine works perfectly.
  QEMU Virtual CPU version 2.5+
  Loading user program...Done.
**********User program is runing**********
  Disk data:
  The Intel386 Processor (1985)
  The Intel386 processor was the first 32-bit processor in the IA-32 architecture
family. ... permitting backward compatibility. The processor also provides a
virtual-8086 mode that allows for even greater efficiency when executing programs
created for 8086/8088 processors.    [END]
  User program terminated,control returned.
```

长句在第 80 列换行，内容与 `diskdata.txt` 一致，没有缺 `[END]`。

## 8. 结果分析

屏幕同时出现内核句子、CPU 品牌、用户程序边框、磁盘原文和“控制权返回”，说明调用链是 MBR → 内核 → 用户程序 → 内核读盘例程 → 回到内核，而不是用户程序自己死循环。

## 9. 问题与修正

源字符串保留了原有拼写 `seen` 和 `runing`。它们是程序里的数据，不是本次引入的错误，实验报告按屏幕原文记录。机器码未改。

## 10. 实验结论

第 13 章已经具备“加载器 + 内核例程 + 用户程序 + 独立数据扇区”的结构。用户程序不直接碰硬盘端口，而是请求内核代读，这是后面系统调用的前身。

# 第15章实验报告

## 1. 实验名称

用硬件任务切换运行一个能报告自身特权级的用户程序。

## 2. 实验目的

- 区分 `call` 任务切换、`jmp` 任务切换和带 NT 标志的 `iretd` 返回。
- 看用户程序怎样从 `CS` 的低 2 位取出当前特权级。
- 修正内核里同样的 `shr` 操作数宽度，并核对本章还缺哪些启动文件。

## 3. 实验环境

| 项目 | 值 |
| --- | --- |
| 系统 | Ubuntu，NASM 2.16.01，QEMU 8.2.2 |
| 源文件 | `c15_core.asm`、`c15.asm` |
| 实验时间 | 2026-10-24 |

## 4. 实验原理

硬件任务切换由 TSS 完成。`call` 一个 TSS 选择子时，处理器保存当前寄存器，装入新 TSS，把 NT 置 1，并把调用者的 TSS 选择子写入新任务的反向链。用户任务结束时，内核看到 NT 为 1，就可以用 `iretd` 沿反向链返回。`jmp` 到 TSS 不设置 NT，也不能靠 `iretd` 返回。

用户程序读取 `CS`，用 `and al,0x03` 留下 CPL，再 `or al,0x30` 变成字符 `'0'` 到 `'3'`。

## 5. 实验步骤

本章没有 MBR，也没有 `run.sh`，不能独立开机。汇编检查是：

```bash
nasm -o c15_core.bin c15_core.asm
nasm -o c15.bin c15.asm
```

## 6. 关键代码说明

`c15_core.asm` 的 0 特权级堆栈使用 `shr dword`。1 级偏移 `0x28` 和 2 级偏移 `0x36` 原来没有宽度。它们和上一行的 `mov ..., ecx` 一样，操作的是双字计数值，右移 12 位后变成页数。

`c15.asm` 只准备查询 CPL 和调用 `@TerminateProgram`。终止时走调用门进入内核，由内核根据 NT 决定 `iretd` 还是 `jmp` 回程序管理器。用户程序自己不判断 NT。

## 7. 实验结果

修正前，内核在第 786 行和第 803 行报 `operation size not specified`。修正后：

| 文件 | 大小 |
| --- | --- |
| `c15_core.bin` | 5916 字节 |
| `c15.bin` | 938 字节 |

没有可启动镜像，因此没有屏幕上的特权级字符。

## 8. 结果分析

用户程序二进制可以生成，说明它的头部、符号表和 32 位入口本身没有汇编错误。缺的是把内核放进扇区 1、把用户程序放进约定扇区并进入保护模式的引导程序。不能用第 13 章的 MBR 硬替，两边的内核入口和加载约定并不相同。

## 9. 问题与修正

两处 `shr` 已写成 `shr dword`，与 0 特权级的写法一致。重新汇编只改变这两条指令的机器码宽度前缀，没有改动特权级判断和任务切换逻辑。

## 10. 实验结论

第 15 章的内核与用户程序现在都能被 NASM 2.16 汇编。源码已经写明 CPL 的取法和三种任务切换的差别，但仓库没有引导扇区，这次实验不能给出屏幕结果。

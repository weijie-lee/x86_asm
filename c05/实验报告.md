# 第5章实验报告

## 1. 实验名称

主引导扇区、显存直接写字符，以及把一个整数拆成十进制数位。

## 2. 实验目的

- 确认 BIOS 把 512 字节的主引导记录加载到 `0x7C00`，并用末尾的 `55 AA` 识别它。
- 弄清实模式“段地址 × 16 + 偏移”和 VGA 文本显存 `0xB8000` 的对应关系。
- 用反复除以 10 的方法，把寄存器里的整数显示成十进制字符。

## 3. 实验环境

| 项目 | 值 |
| --- | --- |
| 系统 | Ubuntu，NASM 2.16.01，QEMU 8.2.2（`qemu-system-i386`） |
| 源文件 | `c05/c05_mbr.asm` |
| 启动方式 | `nasm` 生成 512 字节镜像后，作为 IDE 主盘从硬盘启动 |
| 观察方法 | 从物理地址 `0xB8000` 读出 80×25 的字符单元 |
| 实验时间 | 2026-10-24 |

## 4. 实验原理

文本模式每个字符占 2 字节：偶数字节是 ASCII，奇数字节是颜色。一行 80 个字符，共 160 字节。

本程序把 `ES` 设为 `0xB800 + 80 = 0xB850`。段地址加 80，物理地址加 `80 × 16 = 1280` 字节。`1280 / 160 = 8`，所以写入位置是从 0 计数的第 8 行，也就是通常说的第 9 行。它不是第 2 行。第 2 行的物理地址是 `0xB80A0`。

显示的数来自 `mov ax,0x99`。`0x99` 等于十进制 153。源码里的 `mov ax,number` 被注释掉了，所以屏幕上的数字不是标号 `number` 的偏移。

## 5. 实验步骤

```bash
cd c05
nasm -o c05_mbr.bin c05_mbr.asm
dd if=c05_mbr.bin of=boot.img bs=512 count=1
qemu-system-i386 boot.img
```

`c05_mbr.bin` 为 512 字节，最后两字节是 `55 AA`。

## 6. 关键代码说明

1. 逐个字节把 `"Label offset:"` 写入显存，属性 `0x07`（黑底白字）。
2. `AX = 0x99`。`DS = CS = 0`，因此数据地址要手工加上加载地址 `0x7C00`。
3. 连续 5 次 `div bx`（除数 10），余数依次是个、十、百、千、万位，存进 `number`。
4. 从万位显示到个位，每一位用不同颜色，最后写一个绿色的 `D`，表示十进制。
5. `infi: jmp near infi` 停住，避免 CPU 跑进填充的 0。

标号 `number` 在清单里的汇编偏移是 `0x012E`（十进制 302）。如果恢复 `mov ax,number`，屏幕会显示这个汇编偏移，仍然不是运行时物理地址 `0x7C00 + 0x012E`。

## 7. 实验结果

从 0 计数的第 8 行：

```text
Label offset:00153D
```

前面几行是 SeaBIOS、iPXE 和 `Booting from Hard Disk...`，属于固件，不是本程序写的。

## 8. 结果分析

`0x99 = 153`，五位十进制就是 `00153`，末尾 `D` 与源码一致。颜色按万位到个位依次为红、紫、棕、白、紫，`D` 为绿色。

## 9. 问题与修正

源码注释一度把 `0xB850:0` 解释成“第 2 行”，又在下一句写成“8 行”。按 `1280 / 160 = 8` 复核后，注释已改成第 9 行（从 0 计数为第 8 行），并与这次的屏幕转储对齐。

## 10. 实验结论

主引导扇区可以在没有操作系统的情况下直接写显存。段地址的加减以 16 字节为单位。当前程序演示的是立即数 `0x99` 的十进制显示，不是标号偏移。

# 第7章实验报告

## 1. 实验名称

在主引导扇区中计算 `1 + 2 + … + 100`，并用栈把结果正序显示出来。

## 2. 实验目的

- 用寄存器循环完成累加，核对结果是不是 5050。
- 理解“先压栈的低位、后弹出的高位”，从而不用缓冲区也能正序显示。
- 区分 `loop` 和 `cmp/jle`：本程序的累加不用 `loop`。

## 3. 实验环境

| 项目 | 值 |
| --- | --- |
| 系统 | Ubuntu，NASM 2.16.01，QEMU 8.2.2 |
| 源文件 | `c07/c07_mbr.asm` |
| 启动方式 | `sh run.sh` |
| 实验时间 | 2026-10-24 |

## 4. 实验原理

`DS = 0x7C0`，`ES = 0xB800`，字符串从 `DI = 160 * 8` 写起，也就是第 9 行。字符串 `"1+2+3+...+100="` 的长度用 `start - message` 计算，当前是 14。

累加过程：

```text
AX = 0，CX = 1
重复：AX += CX，CX += 1，直到 CX > 100
```

`CX` 从 1 加到 100 后变成 101，`jle` 不再跳转。`AX = 5050 = 0x13BA`。

显示时 `SS = 0`，`SP = 0`。第一次 `push` 使 `SP` 变成 `0xFFFE`，栈使用该段的高端。除以 10 的余数加 `0x30` 变成 ASCII 后入栈，商为 0 时停止。再逐个 `pop`，高位先出来。

## 5. 实验步骤

```bash
cd c07
sh run.sh
```

引导扇区 512 字节，末尾 `55 AA`。

## 6. 关键代码说明

`or dl,0x30` 与 `add dl,0x30` 对 0–9 的结果相同，因为这些数字的 bit 4 和 bit 5 本来就是 0。

`push dx` 压入的是整个字，但显示时只用 `DL`。栈上多出来的高字节不影响字符。

## 7. 实验结果

从 0 计数的第 8 行：

```text
1+2+3+...+100=5050
```

## 8. 结果分析

`5050 = 100 × 101 / 2`，与闭合公式一致，说明循环包含了 100，也没有多加 101。

第 6 章固定循环 5 次，所以 1234 显示成 `01234`。本章除到商为 0 为止，5050 只有四位，屏幕上没有前导 0。

## 9. 问题与修正

源码注释写“第 9 行”，按从 1 计数是对的；本次转储的行号从 0 计数，所以落在 row 08。注释未改指令。

## 10. 实验结论

实模式下可以用 16 位寄存器完成 5050 这种不超过 65535 的累加。栈的后进先出正好把“低位先得到”的十进制数字翻转成正序。

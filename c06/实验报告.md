# 第6章实验报告

## 1. 实验名称

用 `rep movsw` 批量写显存，并把整数 1234 拆成数位显示。

## 2. 实验目的

- 理解为什么数据要放在 `jmp near start` 后面，避免 CPU 把数据当指令执行。
- 掌握 `cld` 与 `rep movsw`：以字为单位，按递增方向复制。
- 用 `jns` 从高位走到低位，观察循环恰好执行 5 次。

## 3. 实验环境

| 项目 | 值 |
| --- | --- |
| 系统 | Ubuntu，NASM 2.16.01，QEMU 8.2.2 |
| 源文件 | `c06/c06_mbr.asm` |
| 启动方式 | 汇编后把 512 字节写入 `boot.img`，`qemu-system-i386 boot.img` |
| 实验时间 | 2026-10-24 |

## 4. 实验原理

`DS = 0x7C0`，段基址正好是 `0x7C00`，标号偏移可以从 0 用起，不必再加 `0x7C00`。`ES = 0xB800`，`DI = 160 * 8`，字符串从第 9 行开始。

`mytext` 里每个字符后面已经带好属性字节 `0x07`。`(number - mytext) / 2 = 13`，所以 `rep movsw` 复制 13 个字，得到 `"Label offset:"`。

随后 `AX = 1234`，除以 10 五次，余数从低位存进 `number`。显示时 `SI` 从 4 减到 0，`dec si` 后 `jns` 仍跳转；减到 `-1` 时符号标志为 1，循环结束。

## 5. 实验步骤

```bash
cd c06
sh run.sh
```

脚本会删除旧的 `c06_mbr.bin` 和 `boot.img`，重新汇编并启动 QEMU。生成的引导扇区为 512 字节，签名为 `55 AA`。

## 6. 关键代码说明

- `movsw` 把 `DS:SI` 的一个字抄到 `ES:DI`，然后 `SI`、`DI` 各加 2。
- 数位属性是 `0x04`（黑底红字），比第 5 章的逐字节写颜色更集中。
- 末尾 `mov word [es:di],0x0744` 写出黑底白字的 `D`。低字节是字符，高字节是属性。

## 7. 实验结果

从 0 计数的第 8 行：

```text
Label offset:01234D
```

`Label offset:` 为白字，`01234` 为红字，最后的 `D` 为白字。

## 8. 结果分析

1234 的五位十进制形式就是 `01234`。高位补 0 是因为循环固定做了 5 次除法，而不是遇到商为 0 就停止。这和第 7 章“除到商为 0”的写法不同。

## 9. 问题与修正

本次复核没有改指令。`run.sh` 里的 `rm` 在文件不存在时会打印错误，但脚本没有 `set -e`，后面的汇编仍会继续。

## 10. 实验结论

`rep movsw` 适合把已经排好“字符、属性”的数据整块搬进显存。`DS = 0x7C0` 让标号可以直接当段内偏移使用。固定 5 次除法会保留前导 0。

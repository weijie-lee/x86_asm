# 第9章实验报告

## 1. 实验名称

同一加载器分别运行两个用户程序：一个直接操作 RTC 和 8259A，一个调用 BIOS 键盘和显示中断。

## 2. 实验目的

- 沿用第 8 章的加载器，把不同用户程序放在逻辑扇区 100。
- `c09_1.asm`：接管中断 `0x70`，用实时钟每秒刷新一行时间。
- `c09_2.asm`：用 `int 0x10` 的电传输出和 `int 0x16` 的等待按键，对比 BIOS 调用与直接端口操作。

## 3. 实验环境

| 项目 | 值 |
| --- | --- |
| 系统 | Ubuntu，NASM 2.16.01，QEMU 8.2.2 |
| 源文件 | `c09_mbr.asm`、`c09_1.asm`、`c09_2.asm` |
| 脚本 | `run_1.sh` 加载第一个用户程序，`run_2.sh` 加载第二个 |
| 实验时间 | 2026-10-24 09:27（Asia/Shanghai）。客户机 CMOS 时钟与虚拟机 UTC 一致 |

## 4. 实验原理

两个脚本共用同一个 MBR。MBR 只认扇区 100 上的程序头，不关心程序内容。`c09_mbr.asm` 的指令与 `c08_mbr.asm` 相同。文件头原先误写成“代码清单 8-1 / c08_mbr.asm”，本次已改成第 9 章加载器，机器码没有变化。

`c09_1` 修改 8259A 从片的中断屏蔽，并改写中断向量 `0x70`，使其指向自己的 RTC 服务例程。RTC 周期中断到达后读取 CMOS 的时、分、秒并写到屏幕固定位置。

`c09_2` 不接管硬件。`AH = 0x0E`、`int 0x10` 按电传方式输出；`AH = 0`、`int 0x16` 在没有按键时停住。

## 5. 实验步骤

```bash
cd c09
sh run_1.sh
sh run_2.sh
```

实测时镜像为 200 扇区，MBR 在扇区 0，用户程序在扇区 100。`c09_1.bin` 为 784 字节，`c09_2.bin` 为 464 字节，MBR 为 512 字节。

## 6. 关键代码说明

`c09_1` 的提示串是：

```text
Starting...
Installing a new interrupt 70H...
Done.
Clock is now working.
```

时间显示在后面单独的一行，以 `@` 开头。

`c09_2` 的提示串在遇到键盘读取前已经全部输出，所以不按键也能看到邀请信息。按键之后程序才会把字符回显；本次为了保持实验可自动核对，没有注入按键。

## 7. 实验结果

`run_1.sh` 启动约 3 秒：

```text
Starting...
Installing a new interrupt 70H...Done.
Clock is now working.
                                 @  01:27:33
```

再过 3 秒，同一行变为：

```text
                                 @  01:27:36
```

`run_2.sh`：

```text
Hello, friend!
This simple procedure used to demonstrate the BIOS interrupt.
Please press the keys on the keyboard ->
```

光标停在这行末尾，等待 `int 0x16`。

## 8. 结果分析

时间从 `01:27:33` 走到 `01:27:36`，间隔与等待的 3 秒一致，说明 `0x70` 服务例程在持续运行，而不是只打印了一次启动时读到的 CMOS 值。显示的是 UTC，比 Asia/Shanghai 慢 8 小时，所以这次实验对应本地时间 09:27。

第二个程序的三行文本与源码中的 `message` 一致，并且停在提示符后，符合阻塞读键盘的预期。

## 9. 问题与修正

只修正了 `c09_mbr.asm` 开头的文件名和章节说明。重新汇编后与修正前的 MBR 二进制相同。

## 10. 实验结论

第 8 章的加载器可以原样承载第 9 章的两个用户程序。直接写中断控制器能得到每秒更新的时钟；BIOS 中断则用很少的指令完成字符串输出和键盘等待。

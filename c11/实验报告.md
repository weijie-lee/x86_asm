# 第11章实验报告

## 1. 实验名称

进入保护模式，在显存段上显示 `Protect mode OK!`，并核对 32 位栈的 `push byte`。

## 2. 实验目的

- 在实模式里建好 GDT，打开 A20，关闭中断，把 `CR0.PE` 置 1。
- 用远跳转刷新流水线并加载代码段选择子。
- 验证保护模式下 `push byte` 仍使 `ESP` 减少 4，而不是减少 1 或 2。

## 3. 实验环境

| 项目 | 值 |
| --- | --- |
| 系统 | Ubuntu，NASM 2.16.01，QEMU 8.2.2 |
| 源文件 | `c11/c11_mbr.asm` |
| 启动方式 | `sh run.sh`。镜像 200 扇区，只有 MBR 有内容 |
| 实验时间 | 2026-10-24 |

## 4. 实验原理

GDT 放在物理地址 `0x7E00`。描述符 0 必须为空。1 号是代码段，选择子 `0x0008`。2 号把基地址定在 `0xB8000`，选择子 `0x0010`，所以进入保护模式后 `DS` 的偏移 0 就是显存起点。3 号是栈段，选择子 `0x0018`。

远跳转 `jmp dword 0x0008:flush` 同时完成两件事：清空还按 16 位译码的流水线，以及把 `CS` 换成保护模式选择子。

`push byte '!'` 在 32 位栈上会先把立即数扩展成 32 位再压栈，因此 `ESP` 减 4。程序用 `EBP` 记下压栈前的 `ESP`，再减 4 与压栈后的 `ESP` 比较。相等才把弹出的 `'!'` 写到屏幕上。

## 5. 实验步骤

```bash
cd c11
sh run.sh
```

`c11_mbr.bin` 为 512 字节，签名 `55 AA`。进入保护模式后执行 `hlt`。中断已经关掉，处理器停在 `hlt`。

## 6. 关键代码说明

屏幕字符写在 `160 * 8`，只写 ASCII 字节，属性字节沿用显存里原来的值。成功时 `"Protect mode OK"` 后面再补一个 `'!'`。若 `ESP` 的变化不是 4，程序跳到 `ghalt`，感叹号不会出现。

## 7. 实验结果

从 0 计数的第 8 行：

```text
Protect mode OK!
```

## 8. 结果分析

感叹号存在，说明比较结果相等，32 位 `push byte` 确实把栈指针减了 4。字符串本身出现在保护模式数据段指向的显存上，说明 `PE = 1` 之后选择子 `0x0008` 和 `0x0010` 已生效。

## 9. 问题与修正

本次没有修改源码。固件的 SeaBIOS 和 iPXE 文字仍留在更靠上的行，因为本程序没有清屏。

## 10. 实验结论

这是仓库里第一个跑起来的保护模式程序。GDT、A20、关中断、置 `PE`、远跳转这五步之后，可以用段选择子直接写显存，并用栈指针的变化确认处理器已按 32 位栈工作。

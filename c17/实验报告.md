# 第17章实验报告

## 1. 实验名称

用实时钟中断做抢占式调度，让两个用户任务交替打印标记。

## 2. 实验目的

- 确认内核、分页和调用门就绪后，程序管理器会创建两个用户任务。
- 看到任务 A 的分号行和任务 B 的美元符号行出现在同一屏幕上。
- 理解用户程序里的死循环并不独占处理器：RTC 中断可以强制切换 TSS。

## 3. 实验环境

| 项目 | 值 |
| --- | --- |
| 系统 | Ubuntu，NASM 2.16.01，QEMU 8.2.2 |
| 源文件 | `c17_mbr.asm`、`c17_core.asm`、`c17-1.asm`、`c17-2.asm` |
| 磁盘布局 | 扇区 0：MBR；扇区 1：内核；扇区 50：任务 A；扇区 100：任务 B。镜像 500 扇区 |
| 实验时间 | 2026-10-24 |

## 4. 实验原理

两个用户程序的结构相同。任务 A 反复调用 `@PrintString` 打印

```text
  User task A->;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
```

任务 B 打印

```text
  User task B->$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$
```

循环本身不调用让出处理器的例程。内核的 RTC 中断服务在中断里切换任务。任务被打断时不需要知道断点，TSS 保存寄存器。

## 5. 实验步骤

```bash
cd c17
sh run.sh
```

`run.sh` 会先删除旧的 `*.bin` 和 `boot_img`。四个二进制的大小是：MBR 512 字节，内核 4147 字节，两个用户程序各 1108 字节。

启动后等待约 8 秒再读取显存。两个任务都在无限打印，屏幕会不断滚动，一次转储只能看到当时最下面的 25 行。

## 6. 关键代码说明

用户程序通过 SALT 按名字引用 `@PrintString`。内核加载时把名字替换成调用门选择子。`call far [PrintString]` 从用户态进入内核的显示例程，显示完返回用户态，继续死循环。

`c17-1.asm` 末尾的 `@TerminateProgram` 写在 `jmp start` 后面，正常运行到不了。这是故意的：用来对比“协作式退出”和“被时钟抢走处理器”。

## 7. 实验结果

等待约 8 秒时，25 行屏幕的开头是：

```text
  User task A->;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
  User task A->;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
  User task B->$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$
  User task B->$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$
```

其余各行也都是任务 B 的美元符号。任务 A 和任务 B 的标记都出现了。

## 8. 结果分析

一次时钟滴答里，任务可以打印很多行，远超过 25 行。因此一张屏幕通常只剩当前任务刚刚打印的内容，上一任务最多留下几行还没被滚出屏幕的尾巴。这次转储正好停在任务 B 刚接过处理器不久的时候，所以顶部还有两行任务 A。

这不能解释成任务 A 只运行了两次就失效。若 A 从未运行，屏幕上不会有分号行；若 B 从未运行，屏幕上不会有美元符号行。

## 9. 问题与修正

机器码未改。`run.sh` 开头的 `rm *.bin` 在目录里没有二进制文件时会失败，但脚本没有 `set -e`，随后的汇编仍会执行。

## 10. 实验结论

抢占式调度已经生效。两个都不主动让出 CPU 的用户任务，会在 RTC 中断下轮流获得处理器，并在同一块显存上留下各自的标记行。

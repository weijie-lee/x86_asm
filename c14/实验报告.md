# 第14章实验报告

## 1. 实验名称

在内核中加入调用门、局部描述符表、任务状态段和 0–2 特权级堆栈。

## 2. 实验目的

- 读懂调用门如何提供从低特权级进入内核的合法路径。
- 核对任务控制块里各级堆栈的登记方式。
- 让 `c14_core.asm` 能被当前 NASM 汇编通过，并说明仓库为什么还不能直接启动这一章。

## 3. 实验环境

| 项目 | 值 |
| --- | --- |
| 系统 | Ubuntu，NASM 2.16.01，QEMU 8.2.2 |
| 源文件 | 只有 `c14/c14_core.asm` |
| 实验时间 | 2026-10-24 |

## 4. 实验原理

调用门是 GDT 或 LDT 中的系统描述符。用户程序执行远调用时，处理器按门里的目标选择子和偏移进入内核，并可以按门的特权级切换栈。门属性 `1_11_0_1100_000_00000B` 的含义是：存在、DPL 为 3、系统段、类型为 32 位调用门、不复制栈参数。

每个任务有自己的 LDT 和 TSS。TCB 记录 0、1、2 级堆栈的基地址、界限和选择子。堆栈大小以 4KB 页为单位保存，所以写入字节数后再右移 12 位。

## 5. 实验步骤

仓库没有 `run.sh`，也没有本章的 MBR 和用户程序，因此不能按第 13 章的方式做成可启动镜像。本次做的是汇编检查：

```bash
nasm -o c14_core.bin c14_core.asm
```

## 6. 关键代码说明

0 特权级堆栈原来就是：

```text
shr dword [es:esi+0x1a],12
```

1 级和 2 级堆栈写成了 `shr [es:esi+0x28],12` 和 `shr [es:esi+0x36],12`。内存操作数的宽度不能从立即数看出来。`mov [es:esi+0x28],ecx` 已经按 `ECX` 写成双字，右移也必须是双字。`4096 >> 12 = 1`，TCB 中登记的页数是 1。

## 7. 实验结果

修正前 NASM 2.16.01 报错：

```text
c14_core.asm:849: error: operation size not specified
c14_core.asm:866: error: operation size not specified
```

修正后汇编成功，`c14_core.bin` 为 5207 字节。没有配套的 MBR、用户程序和启动脚本，所以没有屏幕输出。

## 8. 结果分析

这不是逻辑改动。同一条指令的 0 特权级版本已经写了 `dword`，1 级和 2 级是漏写操作数宽度。旧版 NASM 可能替程序员猜宽度，2.16 不再猜测。

## 9. 问题与修正

两处 `shr` 已补上 `dword`，并在指令旁注明原因。没有补造本章缺失的 MBR 和用户程序，避免做出一个源码里并不存在的启动流程。

## 10. 实验结论

第 14 章的内核源码现在可以用 NASM 2.16 汇编。它演示的是调用门、LDT、TSS 和分级堆栈的构造方法。要看到屏幕结果，还需要本章没有收入仓库的引导扇区和用户任务。

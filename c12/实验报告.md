# 第12章实验报告

## 1. 实验名称

在 4GB 平坦模型中用代码段别名修改数据，并完成字符串冒泡排序。

## 2. 实验目的

- 建立基地址为 0、界限覆盖 4GB 的代码段和数据段。
- 给同一段物理内存再做一个可写的数据段描述符，作为代码段别名。
- 在只能使用一个 `ECX` 的情况下，用 `push/pop` 实现冒泡排序的双层循环。

## 3. 实验环境

| 项目 | 值 |
| --- | --- |
| 系统 | Ubuntu，NASM 2.16.01，QEMU 8.2.2 |
| 源文件 | `c12/c12_mbr.asm` |
| 启动方式 | `sh run.sh` |
| 实验时间 | 2026-10-24 |

## 4. 实验原理

保护模式代码段不能随便当数据段写。本程序的 2 号描述符是可执行代码，3 号描述符基地址和界限与它相同，但类型是可读写数据，这就是别名。排序时通过别名段读写 `string`。

显存通过另一个基地址为 0 的数据段，用物理地址 `0xB8000` 直接写。`0xB8000 + 160 * 8` 是从 0 计数的第 8 行。排序结果的地址是 `0xB80A0 + 160 * 8 = 0xB85A0`，相对显存起点 1440 字节，`1440 / 160 = 9`，所以是从 0 计数的第 9 行。

待排序字节是：

```text
s0ke4or92xap3fv8giuzjcy5l1m7hd6bnqtw.
```

冒泡排序按 ASCII 升序。外层每轮开始 `push ecx`，内层结束后 `pop ecx`，避免内外层共用计数器时互相冲掉。

## 5. 实验步骤

```bash
cd c12
sh run.sh
```

引导扇区 512 字节，签名 `55 AA`。排序结束后执行 `hlt`。

## 6. 关键代码说明

`"P.M. ok"` 用四个 `dword` 写入，每个双字包含两个“字符 + 属性”。属性 `0x07`。

相邻字符用 `mov ax,[string+bx]` 一次取出，`AL` 是左边，`AH` 是右边。`AH < AL` 时 `xchg al,ah` 再写回。

## 7. 实验结果

```text
08|P.M.  ok
09|.0123456789abcdefghijklmnopqrstuvwxyz
```

行号从 0 计数。`P.M.` 和 `ok` 之间是两个空格。

## 8. 结果分析

排序结果是小数点、数字 `0`–`9`、小写字母 `a`–`z`。小数点的 ASCII 是 `0x2E`，小于 `'0'`；数字小于小写字母。源字符串里的 37 个字符全部在结果中，没有丢字符，也没有多字符。

`P.M. ok` 先于排序结果显示，说明进入保护模式、加载别名段和写显存都发生在排序之前，而且排序没有破坏前面已经写好的显存。

## 9. 问题与修正

注释里“第 10 行”按从 1 计数是对的，容易和转储的 row 09 看成矛盾。已补上一句地址计算：从 0 计数是第 9 行。重新汇编后的机器码与修正前相同。

## 10. 实验结论

代码段别名让保护模式程序仍能修改夹在代码里的初始数据。冒泡排序的结果与 ASCII 升序一致，平坦模型下的比例因子寻址也把结果显示到了预定行。

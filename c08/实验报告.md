# 第8章实验报告

## 1. 实验名称

主引导扇区从硬盘加载用户程序，完成段重定位后把控制权交出去。

## 2. 实验目的

- 通过 IDE 端口 `0x1F0`–`0x1F7` 按 LBA 读取逻辑扇区 100。
- 看懂用户程序头部：总长度、入口点、各段的汇编地址和段重定位表。
- 确认加载器把段的汇编偏移换成实际段地址后，用户程序才能自己显示字符串。

## 3. 实验环境

| 项目 | 值 |
| --- | --- |
| 系统 | Ubuntu，NASM 2.16.01，QEMU 8.2.2 |
| 源文件 | `c08/c08_mbr.asm`、`c08/c08.asm` |
| 磁盘布局 | 扇区 0 是 MBR；扇区 100 起是用户程序。镜像共 200 个扇区 |
| 实验时间 | 2026-10-24 |

## 4. 实验原理

`app_lba_start equ 100` 只在汇编时替换，不占空间。MBR 使用 `vstart=0x7C00`，标号按实际加载地址计算。

用户程序在编译时不知道自己会被放到哪里。头部记录的是相对程序开头的偏移。加载器把它读到内存后，按

```text
实际段地址 = (程序物理地址 + 段内偏移) >> 4
```

回填，再 `jmp far` 到头部给出的入口。

用户程序直接写 `0xB800` 段，显示事先放在程序里的说明文字。

## 5. 实验步骤

```bash
cd c08
sh run.sh
```

脚本依次汇编 `c08_mbr.asm` 和 `c08.asm`，生成 200 扇区的 `boot_img`，MBR 在扇区 0，用户程序在扇区 100。两个产物大小分别是 512 字节和 960 字节。

## 6. 关键代码说明

读盘顺序是：写扇区计数，写 LBA 的低 24 位和高 4 位，向 `0x1F7` 发送读命令 `0x20`，等待状态寄存器的数据请求位，再从 `0x1F0` 用 `insw` 读 256 个字。

用户程序入口调用 `put_string` 两次。字符串以 0 结尾，回车 `0x0D` 把光标式的列号拉回行首，换行 `0x0A` 进入下一行。这里的光标位置是程序自己用变量记的，不是 BIOS 光标。

## 7. 实验结果

用户程序覆盖了部分固件文字，留下的有效内容是：

```text
  This is NASM - the famous Netwide Assembler. Back at SourceForge and in intens
ive development! Get the current versions from http://www.nasm.us/.

  Example code for calculate 1+2+...+1000:

     xor dx,dx
     xor ax,ax
     xor cx,cx
  @@:
     inc cx
     add ax,cx
     adc dx,0
     inc cx
     cmp cx,1000
     jle @@
     ... ...(Some other codes)

  The above contents is written by LeeChung. 2011-05-06
```

第一行在第 80 列被截断，`intensive` 的剩余部分出现在下一行。这是屏幕宽度造成的，不是读盘丢了字符。

## 8. 结果分析

这些字符串都在 `c08.asm` 的 `msg0` 和 `msg1` 里，用户程序能把它们显示出来，说明三件事同时成立：扇区 100 被读入，段地址已重定位，远跳转进入了用户程序。

屏幕上的汇编片段是文本，不是又执行了一次 1 到 1000 的累加。

## 9. 问题与修正

本次没有修改机器码。加载器开头的扩展注释已经覆盖端口、LBA 和重定位，复核时与 `run.sh` 的 `seek=100` 一致。

## 10. 实验结论

从这一章开始，MBR 成为加载器，用户程序可以独立编写。程序头加段重定位，是后面内核加载用户任务的雏形。
